# 第一阶段：UX 致命问题修复（留住来的人）

## 1.1 安装 Toast 通知系统 (sonner)

项目当前零通知库，导出失败完全静默。安装 shadcn 生态的 sonner。

**步骤：**
- `npx shadcn@latest add sonner` — 生成 `components/ui/sonner.tsx`
- `app/layout.tsx`：import `Toaster`，在 `<main>` 后挂载 `<Toaster position="bottom-center" richColors />`

## 1.2 修复所有编辑器的导出失败静默问题

6 个编辑器的 `handleDownload` catch 块，统一改为 `toast.error()` + 成功时 `toast.success()`：

| 文件 | 行号 | 当前代码 | 改为 |
|------|------|---------|------|
| `components/CropEditor.tsx` | 197-199 | `console.error(...)` 静默 | `toast.error("Export failed. Please try a different format or image.")` |
| `components/SmartCropEditor.tsx` | 169-171 | 同上 | 同上 |
| `components/CircleCropEditor.tsx` | 106-108 | 同上 | 同上 |
| `components/OvalCropEditor.tsx` | 129-131 | 同上 | 同上 |
| `components/SocialSafeZoneEditor.tsx` | 187-189 | `console.error(...)` 静默 | 同上 |
| `components/ExportPackEditor.tsx` | 205-209 | `alert(...)` | 改为 `toast.error(...)`，去掉 alert |
| `components/BulkCropEditor.tsx` | 197 | `catch { /* skip */ }` | 统计失败数，完成后 `toast.error("N images failed to export")` |

同时，上传失败也统一从 `alert()` 改为 `toast.error()`（涉及 CropEditor:113、SmartCropEditor、CircleCropEditor、OvalCropEditor、SocialSafeZoneEditor、ExportPackEditor 的图片加载 catch 块）。

成功导出后加 `toast.success("Image downloaded")`（单图）/ `toast.success("ZIP downloaded")`（批量）。

## 1.3 移动端下载按钮可见性

**问题：** `CropEditor.tsx:272` 的 `flex flex-col lg:flex-row` 布局，手机上侧栏（含下载按钮）被 420px 画布推到第二屏。

**方案：** 在编辑器根容器内（`CropEditor.tsx:233` 的 `<div>` 内）新增一个 `lg:hidden` 的固定底部栏，仅在已上传图片且 crop 有效时显示，复用 `handleDownload` 和 `isValidCrop(crop)`：

```tsx
{imageUrl && isValidCrop(crop) && !fullscreen && (
  <div className="fixed bottom-0 inset-x-0 z-40 lg:hidden border-t bg-background p-3">
    <Button onClick={handleDownload} className="w-full h-11 text-base font-medium">
      Download {format.toUpperCase()}
    </Button>
  </div>
)}
```

对 `BulkCropEditor`、`SmartCropEditor`、`CircleCropEditor`、`OvalCropEditor` 做同样的移动端固定下载栏（各自复用自己的 `handleDownload` 和禁用条件）。`ExportPackEditor` 已有 `isExporting` 状态，额外处理。

> 加底部 padding 给编辑器根容器，避免固定栏遮挡内容：`pb-20 lg:pb-0`。

## 1.4 移动端触摸目标修复

将工具栏按钮从 `h-8 w-8`（32px）增大到 `h-10 w-10`（40px，接近 44px 标准）：
- `CropEditor.tsx:246, 253` — 面板折叠/全屏按钮
- `SmartCropEditor.tsx` 同位置按钮

# 第二阶段：SEO 流量增长（拉新的人）

## 2.1 技术 SEO 快速修复

### 2.1a 修复 title 双重后缀
`app/circle-crop-image/page.tsx:11` — title 里有 `| ImageCropKit`，模板又加一次。去掉页面 title 里的 `| ImageCropKit`，让模板统一加。

### 2.1b sitemap lastModified 修复
`app/sitemap.ts:42` — `lastModified: new Date()` 每次构建都是"今天"，Google 会忽略修改信号。改为固定值或基于内容哈希。最简单方案：用一个固定的构建日期常量，仅在内容真改时手动更新。

### 2.1c WebApplication JSON-LD 去重
`components/StructuredData.tsx` — 每个工具页的 WebApplication `name` 都是 "ImageCropKit"。改为接受 `appName` prop，每个页面传各自工具名（如 "Instagram Image Cropper"）。

### 2.1d /trim-screenshot 加入导航
当前 `/trim-screenshot` 在 sitemap 但不在 Sidebar 也不在 Footer。加入：
- `components/Sidebar.tsx` — "Core" 组加 `{ href: "/trim-screenshot", label: "Trim Screenshot" }`
- `components/Footer.tsx` — `toolLinks` 数组加同一项

### 2.1e 给更多工具页加 HowTo schema
当前只有 3 个页面用 `howToSteps`。给以下高流量工具页加 HowTo 结构化数据（争取 Google 富摘要）：
- `/crop-image`、`/crop-image-for-instagram`、`/crop-image-for-tiktok`、`/crop-headshot`、`/crop-image-to-passport-size`、`/circle-crop-image`、`/crop-product-images`、`/bulk-crop-images`

每个页面定义 4-5 步的 `howToSteps` 数组，传给已有的 `StructuredData` 组件。
